The problem

Training exists. Direction doesn't.

Statistical officers take courses on iGOT Karmayogi, but nothing tells them which skills they're weak in or which course closes that gap.

🎯

No diagnosis

Competency gaps in survey methodology, sampling, data quality are invisible — training is guesswork.

🌊

Course ocean

Hundreds of iGOT courses, no mapping to an officer's actual role or weaknesses.

📉

No measurement

Departments can't see readiness across competencies, so training budgets aren't targeted.

The core workflow

One loop: assess → diagnose → train

1 · UPLOADOfficer pastes or uploads training material (PDF / text)
➜
2 · GENERATEEdge function calls Gemini → MCQs tagged by competency
➜
3 · ATTEMPTOfficer takes the quiz; answers scored per competency
➜
4 · MASTERYRPC blends scores into a living competency profile
➜
5 · TRAINGaps query iGOT → ranked recommendations → enroll

Every quiz makes the profile sharper — the loop compounds.

Workflow · step 4

The mastery engine — measured, not vibes

A Postgres RPC scores each quiz per competency. First attempt uses a conservative 40% prior; repeats blend 60% history + 40% latest evidence.

Workflow · step 5

Gaps become ranked courses

🏷️

Tag-matched

Courses are matched by competency tags against each officer's live gap list.

⚖️

Urgency-ranked

Weakest competency first; ties broken by shortest course so officers get quick wins.

🎓

Enroll + track

One click enrolls; recommendations persist per officer with an audit trail.

The iGOT Karmayogi catalog is seeded into Postgres and refreshed by the adapter — recommendations are generated from your own quiz evidence, not a static list.

How it was built
